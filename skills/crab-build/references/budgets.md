# Sizing tool budgets

1. Define and enforce supported input bounds, including response sizes, batch counts, parser complexity and database size. Start with a provisional budget within the destination's ceilings. Exercise representative and worst-case workloads repeatedly, including error paths. Use `crab bench <directory> <tool> --cases cases.jsonl --runs 10`, with representative and largest supported inputs and arranged HTTP responses; the [benchmark guide](https://crabtalk.ai/docs/guides/bench) defines the JSON Lines format. `delay_ms` on a response accounts for memory held while waiting; `--live-http` executes real requests on every repetition.
2. Read the benchmark's own-tool CPU, rows and peak linear memory. CPU is in microseconds and memory in bytes; declaration memory is in MiB. Convert memory to MiB, then start with `ceil(1.5 × maximum)` per key, at least `1`. A budget-stopped run does not measure the work needed to finish. `crab call` and host-test meters include nested calls; `crab bench` separates own usage from chain cost. Exercise called tools separately too.
3. Check every value against the destination host. Default ceilings are `cpu = 100_000` (100 ms), `read = 1_000_000`, `written = 1_000_000`, `memory = 128`. `cpu = 500_000` is 500 ms and is refused by a default host. Omitted keys use defaults: the ceilings above except `written = 10_000` and `memory = 32`. Raising the local CPU ceiling does not change Cloud's.
4. Write the budget, rebuild, redeploy locally and repeat the workload before requesting Cloud approval or publishing. If it cannot fit with headroom, reduce resource use or supported input bounds; use batching or pagination when the operation supports them. Do not just lower the declaration.

`crab budget <service> <tool>` suggests budgets from Cloud's last 30 days. CPU and rows use successful chain totals: maxima below 100 runs, p99 from 100; failed runs are excluded. Memory uses the tool's own recorded peak. The suggestion does not check host ceilings or cover unobserved worst cases. Full workflow and units: [Budgets](https://crabtalk.ai/docs/guides/budgets).

Memory is billed at the reserved budget during execution, waiting on fetches or other services included. Cold code loading is excluded. A tool can lower its budget once with `berm_lang::limit`; its memory argument is in bytes, and `0` leaves a dimension unchanged. See [Budgets in code](https://crabtalk.ai/docs/development/budgets).
